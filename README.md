# Conditional Generative Feature Augmentation for Abnormal-Cut Detection

This repository contains the code, prepared inputs and reported outputs for the MSc dissertation **Evaluating Conditional Generative Feature Augmentation for Abnormal-Cut Detection in CNC Milling**.

The study tests whether adding abnormal-class feature vectors generated by a conditional variational autoencoder (CVAE) improves abnormal-cut detection on held-out Hurco VM20i recordings. Random Forest and XGBoost detectors are evaluated under seven training conditions.

## Main finding

CVAE augmentation did not provide a consistent detection advantage over repeating observed abnormal cuts. It improved mean recall without increasing mean false-alarm rate in two of four classifier and test-cohort comparisons against real-only training. It met the same descriptive criterion in none of the four comparisons with random duplication at matched class counts.

This is a retrospective evaluation of the supplied recordings. It is not evidence of prospective performance on a deployed CNC machine.

## Data

The analysis uses the `imi_vm20i` subset of the Multi-Sensor and MTConnect dataset described by Kim et al. (2026). The retained prepared data contain:

- 1,585 annotated cutting paths from 37 recordings
- 325 abnormal cuts assigned original label 1
- 1,173 normal cuts assigned original label 0
- 87 defective-tool cuts assigned original label 2
- 72 transformed sound, acceleration and MTConnect feature coordinates per cut

For binary detection, label 1 is the positive class. Labels 0 and 2 form the negative class. Label 2 therefore remains distinct from an annotated abnormal cutting condition.

The source dataset is available from Kaggle at <https://doi.org/10.34740/kaggle/ds/8392825> under the Creative Commons Attribution 4.0 International licence. The files in `data/` are prepared derivatives used in this study. Any redistribution must retain source attribution and identify the transformations made.

## Experimental design

The experiment compares the following training conditions:

1. Real-only training
2. CVAE augmentation
3. Reconstruction augmentation
4. Jitter augmentation
5. SMOTE
6. Neighbour interpolation
7. Random duplication

Each condition is evaluated using Random Forest and XGBoost across two recording-holdout configurations and random seeds 11, 29 and 47. Recordings remain intact within each configuration.

The inherited names `id_test` and `ood_test` identify test cohorts. They do not establish a controlled distribution shift. The two configurations also share validation, calibration and `id_test` recordings. They are dependent retrospective evaluations rather than independent replications.

## Reproducing the experiment

The reported run used Python 3.10.10 with CPU execution.

Create and activate a virtual environment, then install the recorded dependencies.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Run a short pipeline check first.

```powershell
python src/train.py --smoke --output results/smoke_check
```

Run the complete seven-condition experiment using a new output directory.

```powershell
python src/train.py --output results/run_new
```

The program refuses to overwrite an existing output directory. This protects the submitted results in `results/final/`.

## Fixed settings

The reported experiment used:

- CVAE latent dimension of 12
- one hidden layer of 96 units in the encoder and decoder
- KL weight of 0.01
- Adam learning rate of 0.001
- 100 CVAE training epochs
- 200 trees per classifier
- candidate maximum tree depths of 3 and 6
- XGBoost learning rate of 0.05
- calibration target of no more than five false alarms among 107 negative calibration cuts
- jitter standard deviation of 0.05 in standardised feature coordinates

The complete machine-readable settings, software versions and input checksums are stored in `results/final/protocol.json` and `results/final/audit.json`.

## Reported outputs

The main files in `results/final/` are:

- `summary.csv` with mean detection metrics
- `metrics.csv` with fit-level metrics
- `predictions.csv` with cut-level scores and alarm decisions
- `feature_quality.csv` with feature resemblance and diversity diagnostics
- `paired_differences.csv` with paired CVAE-minus-control differences
- `comparisons.csv` with descriptive comparison summaries
- `partition_counts.csv` with partition and class counts
- `protocol.json` with fixed settings, versions and code checksums
- `audit.json` with prepared-input checks and file hashes

The `.joblib` and `.pt` files are fitted classifier, scaler and CVAE artefacts. They are not required if the experiment is retrained from the prepared inputs.

## Reproducibility boundary

A repeat run from the prepared inputs reproduced every test alarm decision, the reported detection metrics and the generated-feature diagnostic table. Some Random Forest scores and thresholds differed by no more than `3.34e-16`, which is negligible floating-point variation.

Reproduction begins from the retained feature array and recording manifest. It does not independently reproduce raw sensor alignment, cutting-interval selection or the original expert annotations. Generated observations are 72-coordinate feature vectors. They are not raw sensor waveforms or new physical machining trials.

## Interpretation rule

The descriptive rule treats CVAE augmentation as an observed improvement only when its mean paired recall difference is positive and its mean paired false-alarm-rate difference is non-positive. This rule and the random-duplication control were added after inspection of the original six-condition results. They were not preregistered tests.
